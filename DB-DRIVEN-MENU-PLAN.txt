DECISIONS — RESOLVED
------------------------------------------------------------
A. sort_order:  ADD IT NOW (same pass, not retrofitted later).
   Rationale: once NAV_ITEMS/MOBILE_COLLECTIONS are deleted, ordering
   falls back to creation order/id which is invisible and unpredictable
   to admins. Retrofitting later = second migration + touching every
   wired-up surface (navbar, footer, mobile collections, cart tiles)
   again to add .sort(). ~30 extra minutes now vs 5+ files later.

B. menu_banner chips: DELETE the override system entirely.
   DB categories become the SINGLE source of truth. No parallel
   banner override in Navbar / MobileCollectionList / MobileCategoryNav.
   menu_banner stays valid in the backend placement whitelist but is no
   longer consumed for menu items. If a real "promo pill" need appears
   later, add a small dedicated feature then — easier to add small than
   to unwind two competing systems.
